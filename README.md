# 研途 · StudyPath

用同一份背景对照不同硕士项目的官网要求。当前覆盖英国、新加坡、澳大利亚、美国的 20 个申请规划样本。资料核对日期为 2026-11-12。项目时间和费用附官网来源，动态费用或尚缺的批次信息以官网当期页面为准。

## 运行已打包版本

需要 Java 17 或更高版本。打开 JAR 所在目录，运行 `java -jar study-path-0.1.0.jar`，然后打开 <http://127.0.0.1:8092>。默认使用本机 H2 文件库，记录保存在运行目录下的 `data/`。端口可通过 `STUDY_PORT` 修改。

## 浏览器演示

1. 点 **填入示例** → **生成申请对照**。同一组雅思分数在 UCL 两个项目上得到不同的分数核对结果。
2. 先看相对保底、匹配、冲刺名单，再点项目查看学业成绩与雅思。展开 **查看申请步骤、时间和费用**，核对材料和官网入口。
3. 在 **查官网依据** 中选择一个项目和一个对照项目，点「我雅思 6.5，最低单项 6.0，够吗？」填入问题，然后点 **查依据**。并排查看两张答案卡的结论、依据和待确认事项，也可复制含官网链接的回答。
4. 在 **历史记录** 里打开保存的报告。报告保留当时使用的规则快照。

## 选校分层

- **相对保底候选**：公开且适用的雅思分数线每项至少有 0.5 分余量，其余已收录条件已经核对。无法自动判断的条件由用户按项目和资料快照自行确认。
- **匹配**：公开语言要求已核对，可继续检查学术背景和申请材料。
- **冲刺**：轻微语言或 GPA 差距，或低于官网参考成绩。存在明确的专业或材料差距时归入「目前有差距」。
- **还差信息**：缺少必要成绩、背景信息或适用语言条件。中国百分制、4.0 制、最后 60 学分 GPA、英国学位等级和墨尔本大学 WAM 使用各自口径。系统比较同口径成绩，具体国际学历等效按学校规则。
- 结果页上的 **用 DeepSeek 生成计划** 会根据已算出的分层和公开申请时间整理准备行动。分层和达标判断由规则服务计算。

## 检索对照

`StudyFlowTest` 用 6 道标注了正确条款的样例，对比全库向量检索与按选定项目快照检索。两组使用同一批规则摘要和同一个向量模型。测试会输出实际首条结果命中数。该结果描述这组样例的检索表现，模型生成质量需单独评估。

## 从源码构建

需要 Java 17+、Maven 3.9+、Node.js 20+。先在 `frontend` 运行 `npm ci` 和 `npm run build`，再在 `backend` 运行 `mvn verify`。JAR 在 `backend/target/study-path-0.1.0.jar`。`npm run dev` 的代理指向本地 8092 后端。

## AI 与数据库配置

- Java 比较能够明确判断的条件。成绩缺失、学历换算及需要学校确认的背景显示为待核实。
- LangChain4j 使用内置 BGE-small-zh 量化模型在本机做向量检索。每个项目资料快照有独立的索引，按选中的项目、批次和保存版本检索。索引可从已保存规则重建，业务记录由 JDBC 持久化。
- 雅思问题可以使用问题中明确给出的总分和最低单项，也可以核对本次对照里保存的分数。超出已收录事项、项目或入学批次的问题返回「需要核实」。
- 设置 `DEEPSEEK_API_KEY` 并重启后，后端通过 DeepSeek 的 OpenAI 兼容接口使用 `deepseek-flash`。也支持原有的 `STUDY_MODEL_KEY`、`STUDY_MODEL_BASE_URL` 和 `STUDY_MODEL_NAME` 配置。模型返回结构化解释和引用标识，后端检查引用是否来自当前项目、批次和快照。模型不可用或引用不合格时保留本地规则解答。配置云模型后，请避免在问题里填个人信息。已保存的申请背景不会自动发给模型。
- 规则问答还会提供下一步操作。例如雅思单项不足时列出差多少分，资料缺失时提示补哪项，学历和材料问题则提示要核对的文件和官网章节。
- 可选 MySQL。先创建空库，再将 `STUDY_DB_URL` 设为 `jdbc:mysql://127.0.0.1:3306/study_path`，并设置 `STUDY_DB_USER`、`STUDY_DB_PASSWORD`。
- 当前为本机单用户演示，默认只监听 `127.0.0.1`。业务报告会保存表单条件。共享部署需要加入账号、数据隔离和运维配置。

## Python LangChain 服务

Java 先按项目和入学批次检索公开条款。开启 `ai-service` 后，Java 把限定范围内的资料和问题交给 Python LangChain。LangChain 组合提示词、调用 DeepSeek 并解析 JSON，Java 核验问答引用并保留分数判断。申请准备计划也走这条生成链路。网页会显示实际使用的框架。

1. 使用 Python 3.12，在 `ai-service` 运行 `python -m pip install -r requirements.txt`。
2. 为 Python 设置 `DEEPSEEK_API_KEY` 与 `STUDY_LANGCHAIN_TOKEN`。后者使用随机生成的本地服务令牌。启动 `python -m uvicorn app:app --host 127.0.0.1 --port 8094 --no-access-log`。
3. 为 Java 设置 `STUDY_LANGCHAIN_URL=http://127.0.0.1:8094` 和与 Python 相同的 `STUDY_LANGCHAIN_TOKEN`，再启动 JAR。此模式下模型 Key 只需要配置给 Python 进程。
4. 在 `ai-service` 运行 `python -m unittest -v` 检查提示词、JSON 解析和本机接口鉴权。开启服务后可点「用 DeepSeek 生成计划」或发起一条带依据的问答。

`programs.json` 中的每条材料包含学校官网链接、章节和人工整理摘要。新增年份或规则版本时，添加带新快照日期的条目。真实申请请在提交前核对学校官网原文。
